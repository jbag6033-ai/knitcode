# KnitCode Flow

함수 중심의 호출 흐름과 별도의 Git 변경 맥락 패널을 제공하는 VS Code 확장 실험판입니다. 원래 KnitCode와 별도 ID(`knitcode-local.knitcode-flow`)를 사용하므로 동시에 설치할 수 있습니다.

## 설치 및 실행

1. VS Code 확장 메뉴의 **Install from VSIX…**에서 `dist/knitcode-flow-0.1.1.vsix`를 설치합니다.
2. 분석할 Python 프로젝트 폴더를 엽니다. 첫 확인에는 `tests/fixtures/advanced_project`를 사용하세요.
3. 명령 팔레트(`⌘⇧P`)에서 **KnitCode Flow: Open Call Flow**를 실행합니다.
4. 분석 전 열려 있던 파일의 첫 함수가 시작점이 됩니다. 왼쪽 트리에서 다른 함수를 선택할 수 있습니다.

Python 실행 오류가 나면 `knitcodeFlow.pythonPath`에 Python 3.10+ 경로를 입력합니다. 비어 있으면 기존 `knitcode.pythonPath` 설정을 사용하고, 개발 소스 실행 시 상위 프로젝트의 `Knitcode/bin/python`, 그 외에는 `python3`를 사용합니다.

이 머신의 예시: `프로젝트 가상환경의 Python 실행 파일 경로`

## 화면 사용법

- 왼쪽: 파일과 함수 검색·선택. 파일의 **파일 변경 맥락**을 선택하면 파일 내 코드 목록과 이력을 표시합니다.
- 가운데: **호출자 → 선택 함수 → 호출 대상**을 단계별로 배치합니다. 실제 확인된 인접 단계 호출에 연결선을 그립니다. **+ 단계 / − 단계**로 1~3단계를 조절하며 가로 스크롤할 수 있습니다.
- 각 카드의 **코드 ↗**는 정의 위치를 열고, **중심으로**는 해당 함수를 탐색의 시작점으로 바꿉니다. **이전 선택**으로 돌아갈 수 있습니다.
- 아래: 선택 함수의 직접 호출 관계와 소스 위치. 위치 버튼은 정의 줄이 아닌 실제 호출 줄을 엽니다. 재귀·단계를 건너뛰는 관계도 이 목록에서 확인합니다.
- 오른쪽: 현재 함수 소속 파일의 **함께 변경** 또는 **변경 이력**. 공동 변경 횟수를 막대로 비교하고, 커밋을 펼쳐 patch를 열 수 있습니다. 파일 선택 시 그 파일의 변경 맥락으로 이동합니다.
- 파일을 저장한 뒤 **재분석**으로 갱신합니다. 기존 선택을 유지합니다.

순환 호출은 같은 방향에서 이미 방문한 노드를 반복 확장하지 않습니다. 단계별 노드가 20개를 넘으면 추가 항목을 펼칠 수 있습니다. 전체 그래프를 한 화면에 배치하는 방식과 달리 선택 코드의 읽기 흐름에 집중합니다.

## 범위와 검증

분석기는 기존 버전과 같습니다. Python 정적 분석 후보이며, 외부 호출·미해석 호출은 흐름도에서 제외합니다. 저장된 소스만 분석하고 자동 갱신하지 않습니다. Git은 기본 최근 90일, 최대 300개 비병합 커밋이며 2회 이상 공동 변경만 표시합니다. 50파일 초과 커밋은 공동 변경에서 제외합니다. 이름 변경은 추적하지 않습니다.

기존 대형 프로젝트 분석의 성능 한계는 그대로이며 180초 후 종료합니다. 두 확장의 Git 기간·커밋 한도는 각각 독립 설정입니다. 두 확장은 각자의 기존 인터페이스를 유지하며 같은 최신 분석기를 포함합니다. 이전 0.1.0 VSIX도 보관합니다.

Python 회귀 테스트, 새 패키지 ID/리소스 검증, JavaScript 문법 및 모의 DOM에서 선택·단계 확장·공동 변경 동작을 확인합니다. 실제 VS Code Extension Host 설치와 화면 배치는 별도 확인이 필요합니다.

재패키징은 프로젝트 루트에서 실행합니다. 기존 VSIX를 덮어쓰지 않습니다.

```sh
.venv/bin/python scripts/package_flow_extension.py
```

## 0.1.1 업데이트

기존 화면·명령·설정은 유지하고 최신 분석기를 포함했습니다. 상속/인자 바인딩/컨테이너/with/제한된 동적 메서드 추론 개선과 ValueFlow 정적 탐색 캐시를 반영합니다. autojump 분석 중앙값은 개발 환경에서 5.10초→1.67초였으며 전체 저장소 성능은 별도 검증이 필요합니다. 검토용 benchmark 정답 수정안은 확장에 포함하지 않습니다.

이미 0.1.0을 설치했다면 이 VSIX를 설치한 뒤 VS Code의 Reload Window를 실행하고 기존 패널을 닫아 명령으로 다시 열어주세요. 업데이트 이후 파일 저장 시에는 기존처럼 재분석을 누릅니다. 소스 변경이 설치된 확장에 자동 반영되지는 않습니다.
