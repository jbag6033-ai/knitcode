# KnitCode 개선 이력과 PyCG 대비 평가

> GitHub 도입 커밋을 그대로 복원해 재평가한 결과부터 현재까지의 변화다. 전체 정답 기준으로 Fabric F1은 **27.23% → 73.35%**로 상승했다. 현재 5개 프로젝트 중 **autojump와 Sublist3r에서 논문 PyCG보다 F1이 높다.** Fabric은 PyCG보다 **2.61%p 낮다.**

## 1. 비교 기준

| 항목 | 기준 |
|---|---|
| 출발 코드 | 현재 저장소의 GitHub 도입 기준 커밋 `06422ca` — `Expand static call graph and object flow analysis` |
| 시작점 측정 | 해당 커밋의 엔진을 임시 디렉터리에 복원해 이번에 소급 측정. 원본 엔진은 수정하지 않음 |
| 평가 대상 | PyCG 논문의 5개 프로젝트: Fabric, autojump, asciinema, face_classification, Sublist3r |
| 입력 소스·정답 | `knitcode_test`에 보관된 PyCG 원본 데이터. 최신 평가에서 원본 재현 패키지와 파일 목록·소스 해시·정답 일치 확인 |
| 호출 범위 | 내부 호출, 외부 패키지 호출, 표준 라이브러리·내장 함수 호출을 포함한 전체 ground truth |
| 채점 방식 | 원본 PyCG 재현 패키지의 Precision·Recall 함수. F1은 두 값의 조화평균 |
| PyCG 수치 | 논문 Table IV에 보고된 반올림 Precision·Recall로 계산한 F1. PyCG를 새로 실행한 결과는 아님 |

**출발 코드에도 객체 흐름 분석과 선택적인 dependency 소스 분석은 있었다.** 다만 기본 출력에는 외부 호출 그래프가 없어, 도입 당시 수치를 전체 ground truth로 채점하면 재현율이 낮다. 따라서 초기 상승 전체를 내부 추론 정확도 향상으로 해석하면 안 된다. 외부 호출 지원 범위를 넓힌 효과와 정확도를 높인 효과가 함께 포함돼 있다.

이 문서의 성능 지표는 **호출 그래프 정확도**다. 실행 속도 개선을 의미하지 않는다.

## 2. 도입 이후 무엇을 개선했나

| 단계 | 발견한 문제·부족한 기능 | 개선 내용 | 확인된 효과 |
|---|---|---|---|
| ① Python 의미 분석 보강 | 인코딩 선언, await, 컨테이너 인덱싱, match/finally, 동적 바인딩에서 누락·오연결 | 인코딩 처리, await 시점의 값 추적, 작은 컨테이너 요소 추적, 분기·반환 병합, 미확인 decorator와 메서드 변경에 대한 연결 유보 | 개발용 집중 사례의 대상 집합 일치 **9/22→15/22**, FP **5→1**, FN **11→6** |
| ② Sublist3r·Flask 실전 패턴 보강 | 상속·콜백·스코프·classmethod에서 잘못된 연결 또는 누락 | 표준 라이브러리 MRO 처리, sorted key 콜백, lexical scope와 클래스 namespace 구분, classmethod의 클래스 수신자 처리 | Sublist3r 내부 호출 TP **83→115**. Flask의 직접 바인딩 검토 14곳에서 일치 **12→14**, 오연결 **2→0** |
| ③ 더 큰 프로젝트와 descriptor 지원 | 중첩 클래스·기본 인자·property의 암묵적 실행을 놓침 | 중첩 클래스와 별칭 생성, 단순 기본 인자 전달, property getter 호출·반환 추적, 단독 classmethod 본문 분석 | autojump 내부 호출 TP **147→154**. Fabric 내부 호출 TP **38→42**. 이 초기 property 변경에서는 정답 기준 FP도 증가했음 |
| ④ 외부 호출 지원 및 전체 정답 평가 | 내부 호출만으로는 논문과 같은 범위를 평가할 수 없음 | import 별칭·인자·필드의 외부 참조, 단일 외부 기반 클래스·super의 기호적 호출 후보를 별도 그래프로 출력. 논문 입력 범위와 전체 scorer 적용 | 전체 정답 기준 Fabric F1 **71.75%**. 이후 단계와 비교하는 공통 기준 확보 |
| ⑤ 오탐·미탐 동시 개선 | 내장 클래스 상속·소비되는 map 콜백 누락, 잘못된 외부 반환값·중첩 호출 경로 | list/dict 상속 메서드, 소비 지점 map 콜백 추적, 알려진 primitive 반환 계약, 문자열 기반 inline 추측 제거 | Fabric TP **240→245**, FP **48→43**, FN **141→136**, F1 **71.75%→73.24%** |
| ⑥ 외부 factory 반환 계약 보완 | mkdtemp 반환값을 factory 함수 자체의 인스턴스로 오인 | 공식 API 계약에 따라 반환 객체를 opaque로 유지하고 가짜 `mkdtemp.join` 경로 차단 | Fabric FP **43→42**, TP·FN 유지, F1 **73.24%→73.35%** |

①~③의 수치는 각 단계 당시의 별도 집중 검증 또는 **내부 호출 평가**다. 이 수치들을 아래 전체 정답 기준의 F1 곡선에 섞지 않았다. Flask 검토 표본은 논문 벤치마크가 아니며 전체 프로젝트 정확도 추정치가 아니다.

## 3. 단계별 F1과 논문 PyCG 비교

모든 열은 동일한 프로젝트 입력·전체 ground truth·채점 규칙을 사용한다. 도입 당시 값은 해당 Git 커밋을 소급 평가한 값이다.

| 프로젝트 | 도입 당시 기본 출력 | 외부 호출 지원 후 | 오탐·미탐 동시 개선 후 | 현재 | 논문 PyCG | 현재−PyCG |
|---|---:|---:|---:|---:|---:|---:|
| fabric | 27.23% | 71.75% | 73.24% | 73.35% | 75.96% | -2.61%p |
| autojump | 42.75% | 80.72% | 81.02% | 81.02% | 80.93% | +0.09%p |
| asciinema | 45.44% | 77.14% | 77.39% | 77.39% | 80.95% | -3.57%p |
| face_classification | 36.47% | 92.13% | 92.66% | 92.66% | 94.35% | -1.69%p |
| Sublist3r | 33.95% | 78.06% | 78.38% | 78.38% | 75.89% | +2.50%p |

**현재 비교:** autojump와 Sublist3r에서는 논문 F1을 넘었고, Fabric·asciinema·face_classification에서는 아직 낮다. 5개 프로젝트 전반에서 PyCG보다 우수하다고 결론 내릴 단계는 아니다.

PyCG 논문의 asciinema 재현율은 68.0%이며, 재현 패키지 표에는 68.3%로 기록돼 있다. 위 표는 논문 68.0%를 사용했다. PyCG F1은 반올림된 P/R에서 계산했으므로 작은 차이는 신중하게 해석해야 한다.

## 4. Fabric의 개선 과정 상세

| 단계 | TP | FP | FN | 정밀도 | 재현율 | F1 | PyCG F1 대비 |
|---|---:|---:|---:|---:|---:|---:|---:|
| GitHub 도입 당시 기본 출력 | 61 | 6 | 320 | 91.04% | 16.01% | 27.23% | -48.73%p |
| 외부 호출 지원 | 240 | 48 | 141 | 83.33% | 62.99% | 71.75% | -4.22%p |
| 오탐·미탐 동시 개선 | 245 | 43 | 136 | 85.07% | 64.30% | 73.24% | -2.72%p |
| 현재 | 245 | 42 | 136 | 85.37% | 64.30% | 73.35% | -2.61%p |
| 논문 PyCG | — | — | — | 98.30% | 61.90% | 75.96% | 기준 |

Fabric의 초기 도입 대비 변화는 **TP +184개, FN −184개, F1 +46.12%p**다. 외부 호출을 새로 보고하면서 도입 당시보다 FP가 늘었다.

외부 호출 지원 이후의 정확도 개선만 보면 **TP 240→245, FP 48→42, FN 141→136**이다. 이 구간에서는 새 오탐을 추가하거나 기존 정답을 잃지 않으면서 F1을 **71.75%→73.35%**로 높였고, PyCG와의 F1 격차를 **4.22%p→2.61%p**로 줄였다.

## 5. 현재 어디까지 왔나

| 프로젝트 | 우리 정밀도 | 우리 재현율 | 우리 F1 | PyCG 정밀도 | PyCG 재현율 | PyCG F1 |
|---|---:|---:|---:|---:|---:|---:|
| fabric | 85.37% | 64.30% | 73.35% | 98.30% | 61.90% | 75.96% |
| autojump | 94.09% | 71.14% | 81.02% | 99.50% | 68.20% | 80.93% |
| asciinema | 83.85% | 71.85% | 77.39% | 100.00% | 68.00% | 80.95% |
| face_classification | 91.11% | 94.25% | 92.66% | 99.50% | 89.70% | 94.35% |
| Sublist3r | 90.35% | 69.21% | 78.38% | 98.80% | 61.60% | 75.89% |

현재 5개 프로젝트 모두에서 재현율은 논문 값보다 높고 정밀도는 낮다. 따라서 다음 개선의 중심은 **찾아낸 정답을 유지하면서 잘못된 호출 후보를 줄이는 것**이다. Fabric은 재현율 **64.30% vs 61.90%**지만 정밀도 **85.37% vs 98.30%**의 차이가 남아 있다.

## 6. 회귀 검증과 해석상 주의점

| 항목 | 확인한 내용 |
|---|---|
| 최신 자동 테스트 | **403개 통과** |
| 최근 정확도 개선의 회귀 조건 | 5개 프로젝트 모두 **새 FP 0개, 기존 TP 손실 0개** |
| 검사 단위 | FP/FN 수뿐 아니라 caller–callee 쌍을 비교. 기존 오탐을 다른 오탐으로 바꿔도 실패 |
| 원본 데이터 유지 | 프로젝트 소스·ground truth 미수정. 정답 기반 예외나 오탈자 보정 없이 채점 |
| 정답의 중복 처리 | 원본 scorer대로 중복 항목도 재현율에 반영. TP/FP/FN의 고유 쌍 수와 구분 |
| 남은 Fabric 오탐 | 정답 기준 42개. 실제 property 접근 누락 후보와 외부 API 이름·정의 경로 차이도 포함 |
| 아직 주장하지 않는 것 | 임의 프로젝트의 오탐·미탐 비증가 보장, 런타임 완전성, 전체 Python 지원, 실행 속도 우위 |

정답에 없는 간선을 무조건 삭제해 점수를 높이지 않았다. 예를 들어 소스 import 경로와 정답의 다른 경로, property의 암묵적 호출 등은 근거 검증이 필요하다.
