# KnitCode · VS Code 확장 초안

제안 HTML의 탐색 흐름을 실제 Python 정적 분석 결과에 연결합니다. 별도 웹 서버, npm 설치, CDN 연결 없이 VS Code Webview에서 실행합니다. Python 3.10 이상과 Git(이력 기능 사용 시)이 필요합니다. 분석 대상 코드는 실행하지 않습니다.

## 설치하고 실행하기

프로젝트 루트에서 현재 분석기를 포함한 VSIX를 만듭니다.

```sh
.venv/bin/python scripts/package_extension.py
```

VS Code의 Extensions 메뉴에서 **Install from VSIX…**를 선택하고 `dist/knitcode-0.1.1.vsix`를 설치합니다. 분석할 Python 프로젝트 폴더를 열고 명령 팔레트에서 **KnitCode: Open Code Map**을 실행하세요. Python을 찾지 못하면 설정의 `knitcode.pythonPath`에 Python 3.10 이상 실행 파일의 절대 경로를 입력합니다. 이 프로젝트에서는 `프로젝트 가상환경의 Python 실행 파일 경로`을 사용할 수 있습니다.

첫 실행은 `tests/fixtures/advanced_project` 폴더를 VS Code로 열어 확인하는 것을 권장합니다. `main → OrderService.create_order → calculate_price / save_order / validate` 관계를 확인할 수 있습니다. KnitCode 저장소 전체를 분석하는 실험은 기존 값 흐름 분석의 긴 처리 시간으로 중단했습니다. 확장은 180초 후 분석을 종료하며, 큰 프로젝트의 성능은 아직 보장하지 않습니다.

1. 왼쪽에서 파일을 펼치고 함수를 선택합니다.
2. 그래프 노드를 선택하고 **주변 연결 펼치기**로 탐색합니다.
3. **코드 열기**, 호출 관계 목록을 누르면 정의/호출 줄로 이동합니다.
4. **소속 파일 관계**에서 금색 공동 변경 연결을 선택하면 관련 커밋이 표시됩니다.
5. 커밋 버튼은 해당 커밋의 patch를 VS Code 읽기 문서로 엽니다.
6. 수정한 파일을 저장한 뒤 **재분석**으로 갱신합니다.

개발할 때에는 VS Code에서 **Debug: Add Configuration… → VS Code Extension Development** 구성을 만들고 `--extensionDevelopmentPath`를 이 `vscode-extension` 폴더로 지정해 실행할 수도 있습니다. 소스 실행은 상위 디렉터리의 분석기를 사용하고, VSIX 설치는 포함된 분석기를 사용합니다.

## 계산 기준과 범위

- 구조적 중요도: 함수에 들어오는 서로 다른 호출자 수. 0–1 낮음, 2–4 보통, 5 이상 높음. 파일 집계 점수는 아직 없습니다.
- 파일 변경 빈도: 기본 최근 90일, 최대 300개 비병합 커밋 중 해당 파일 변경 횟수. 0–2 낮음, 3–9 보통, 10 이상 높음. 기간과 커밋 수는 설정에서 변경합니다.
- 공동 변경: 선택된 관찰 범위에서 현재 분석 대상 두 파일이 2회 이상 함께 바뀐 경우. 50파일 초과 커밋은 공동 변경 계산에서 제외하고 횟수를 표시합니다. 인과관계를 뜻하지 않으며 파일 이름 변경 추적은 아직 지원하지 않습니다.
- 정적 분석 후보이므로 실제 런타임 관계와 다를 수 있습니다. 미해석 호출에는 외부 라이브러리/builtin도 포함됩니다.
- 저장된 `.py` 소스 기준이며 Git/가상환경/benchmark/node_modules 등을 제외합니다. 문법/인코딩 오류 파일은 제외 이유를 표시합니다.
- 다중 루트는 실행 시 폴더 하나를 선택합니다. 신뢰한 workspace에서만 실행합니다.
- 그래프는 최대 60노드를 표시하고 전체/표시 수를 공개합니다. 더 큰 프로젝트의 레이아웃, 자동 갱신, import 관계, native TreeView, Marketplace 배포는 후속 작업입니다.

## 검증 상태

Python 분석→JSON과 Git 이력/공동 변경/하위 폴더 처리 및 VSIX 내용은 자동 검증합니다. 실제 VS Code Extension Host에서의 화면 동작과 설치는 별도 확인이 필요합니다.

## 0.1.1 업데이트

기존 화면·명령·설정은 유지하고 최신 분석기를 포함했습니다. 상속/인자 바인딩/컨테이너/with/제한된 동적 메서드 추론 개선과 ValueFlow 정적 탐색 캐시를 반영합니다. autojump 분석 중앙값은 개발 환경에서 5.10초→1.67초였으며 전체 저장소 성능은 별도 검증이 필요합니다. 검토용 benchmark 정답 수정안은 확장에 포함하지 않습니다.

이미 0.1.0을 설치했다면 이 VSIX를 설치한 뒤 VS Code의 Reload Window를 실행하고 기존 패널을 닫아 명령으로 다시 열어주세요. 업데이트 이후 파일 저장 시에는 기존처럼 재분석을 누릅니다. 소스 변경이 설치된 확장에 자동 반영되지는 않습니다.
